# Arjun Agrawal · IB DP Economics

**Think like an economist.**

A free, browser-based learning environment for IB Diploma Programme Economics, built by
**Arjun Agrawal**: IB DP Facilitator in Economics, Business Management and Global Politics,
Economics educator, UPSC CSE mentor and resource creator.

Learn the concept. See the model. Build the chain. Stress-test the argument. Make the
judgement. Apply it under pressure.

---

## What this is

Not a content repository. A system for practising the sequence that IB DP Economics
actually assesses:

> cause → behaviour → market effect → second-round effect → wider consequence → evaluation → judgement

Everything runs in the browser. There is no account, no server, no tracking, and no AI API.
A student can download `index.html`, double-click it, and work offline.

## Who it is for

- **Students** taking IB DP Economics at SL or HL, at any point from first lesson to final exam.
- **Teachers** who want accurate diagrams, classroom-projectable models, misconception tools,
  question banks and assessment reasoning they can use directly in a lesson.

## Educational philosophy

A definition recalled without its mechanism is inert. A diagram drawn without an argument
attached to it earns almost nothing. So the platform puts the mechanism first, and everything
else attaches to it:

**Understand → Visualise → Connect → Analyse → Stress-test → Judge → Apply**

Around that spine sits the structure the guide itself uses: six real-world issues, read through nine
key concepts, across four units. Every subtopic in the curriculum explorer answers the same three
questions: what do I need to know, what must I be able to do, and how could this be assessed.

That framework is a teacher's framing, not IB terminology, and the platform labels it as such.

## Honesty rules the platform holds itself to

- **Five claim layers, never blurred:** official IB information · established economic theory ·
  Arjun Agrawal teaching frame · teacher-created practice · constructed teaching data.
  Assessment claims carry a source, a version and a verification date. Nine of them are also
  checked against the IB's own pages, with a link to each, under **Exam → IB reference layer
  → Live verification**. One of the nine could not be established and is shown as not verified
  rather than quietly dropped.
- **No fabricated data.** No figure is asserted in the Real World section; every story routes
  its numbers to named primary institutions. All lab and drill figures are labelled as
  constructed teaching data.
- **The diagnostic is rules-based**, teacher-designed, and built on the published assessment
  framework. It is not an official IB mark and the platform says so wherever it appears.
- **No fabricated social proof.** No testimonials, ratings, student counts, success rates or
  grade guarantees anywhere.
- **No invented credentials.** The About page contains only details supplied by Arjun Agrawal.
- **No universal definitions where none exist.** Definitions of recession, for instance, are presented
  as varying between countries and institutions rather than as a single settled rule.
- **Gaps are declared.** The diagram atlas lists the plates the guide names that this build does not
  yet draw, and the quality report lists what the self-tests do not cover, rather than implying
  coverage that does not exist.
- **Nothing pretends to be live.** There is no data feed. The "Economics now" page says so, and routes
  every current figure to the body that publishes it.

## Technology

- A single self-contained `index.html`. No framework, no bundler, no dependencies to install.
- **One file, deliberately, with one exception.** Everything the platform does is in `index.html`,
  because that is what makes it work from a memory stick, from an email attachment and from a
  `file://` path with no server. Parse cost was measured rather than assumed, over three cold
  loads of the packaged file: first contentful paint 280 to 288 ms, `DOMContentLoaded` 1.66 to
  1.70 s, 964 DOM nodes after the home page renders, a 20 MB heap, and the slowest render in the
  build is the 34-plate diagram atlas at 42 ms. Sixty navigations across all 151 routes leave the
  heap unchanged. The parse figure grew with the bundled copies of the two corpora, which is the
  cost of a file that still works when it arrives on its own. Splitting the remaining datasets
  would have traded that for a tree of files that breaks the moment one of them is lost. The one
  exception is the pair of reference corpora, `assets/data/exam-dna.js` and
  `assets/data/real-world.js`, which are loaded with a plain `<script src>` because they are
  reference data rather than behaviour and because each must be auditable on its own. Neither is
  required, and neither can leave a gap. Both also travel inside `index.html`, as JSON held in
  function bodies the engine skips until they are called. If the copy in `assets/data` loads, the
  bundled copy is never read; if it does not, the platform adopts the bundled copy and nothing on
  the screen changes. A single copied `index.html` runs the full 1,659 checks with nothing failing
  and has all 203 cases, all 212 analysed questions and all ten carousels.
- **Diagram Engine 2.0.** Every quantitative diagram is generated from a declared model:
  equations, parameters, an equilibrium solver, then curves plotted from those same equations.
  No intersection is positioned by hand. After rendering, the engine measures the distance in
  rendered pixels between every labelled point and the curves it is supposed to lie on; a point
  that misses fails validation and the diagram is reported as failed rather than displayed as
  correct. **27 model-driven diagrams, 27 validated, 0 failed, largest miss 0.000 px against a
  0.75 px tolerance.** The seven remaining plates are flow diagrams and schematics with no
  equilibrium to solve; they are declared as such rather than counted as validated.
- The equations, parameters, solved equilibria and per-point validation for every diagram are
  visible to teachers at **Lab → Model integrity**.
- Fonts load from Google Fonts when online and fall back to system fonts when not. Nothing
  else is fetched.
- Progress is stored in `localStorage` on the student's own device. Migration from an earlier schema
  is tested end-to-end and preserves keys the current build does not recognise. The rename from
  the earlier name moved the stored key with it and copied the old record across rather than
  discarding it; a test seeds a profile in the old shape and asserts that nothing is lost.
- **A progressive web app.** `manifest.webmanifest` and `service-worker.js` make the platform
  installable and genuinely usable without a connection once it has been opened, with icons
  generated from the supplied logo. Registration happens only on a secure origin, after load, and
  nothing external is cached or claimed to work offline.
- **Every page has an address.** Moving between sections, tabs and items updates the address
  bar (`#/world`, `#/lab/diagram-atlas/<diagram>`, `#/learn/concept-spine/<concept>`), so the
  browser's Back and Forward buttons move through the platform rather than out of it, a refresh
  keeps the reader where they were, and a teacher can bookmark or send a link to one page. The
  address is a hash, so it works from a `file://` path and from a subdirectory with no server
  rewrite rules; the short form the install shortcuts use (`#mind`, `#session`, `#video`) works
  too. The router writes nothing while the self-tests run, leaves assignment links (`#assign=…`)
  untouched and stores nothing. A reload, a Back step into the platform or a deep link skips the
  five-second opening sequence; a fresh visit still plays it.
- A command palette opens on `/` or `Ctrl`/`Cmd` + `K` and reaches every section, every printable and
  every indexed item of content.
- The build includes a self-test of **1,659 checks** reported across every area of the build: startup, printing,
  navigation, mobile, desktop, resources, Google Drive, IB Economics, TOK, economics theory, calculations,
  diagrams, mindmap integrity, topic architecture, assessment, IA, student features, teacher features,
  progress, storage, export and import, contact links, tutorials, branding, accessibility, performance,
  content integrity, video learning, tools, timed sessions, my economics, the opening sequence,
  installability and offline behaviour, Exam DNA, the paper labs, the analytical layers, the
  independent-platform statement and the real-world collection. Open the browser console for the category report, or read it on
  the page at **About → Quality report**, with the counted content report at **About → Content report**.
  An area with no assertions behind it is reported as untested rather than as a pass. In this release
  every area has assertions behind it and **every check passes**.
- **The self-tests change nothing.** They may inspect, calculate and render, but they cannot print,
  download, navigate, open a dialogue or touch saved data: the storage layer is sandboxed for the
  duration of a run and the sandbox is discarded afterwards. A guard records any attempt to print
  outside a user action and reports it as a failure.
- The economic models are checked against an **independent algebraic solution** of the same
  problem, at baseline, under a shock, inverted, and at the boundaries, rather than against
  themselves.
- Every calculation is exercised on forty generated inputs and on zero, negative and decimal values,
  and its marking tolerance is checked to be tight enough to reject an answer that is out by half.

## Mindmaps

The knowledge map shows how syllabus topics connect to one another. A mindmap shows something
different: how an economist moves through one of them, from the concept to the mechanism to the
model to the judgement, and where each step can be tested. Both are kept, and they link to each
other.

Forty-two maps in three classes:

- **Ten core maps**, one per strand of the course: foundations, markets, elasticity, government
  intervention, market failure, market structure, economic activity, policy, the global economy
  and development. These are the original ten, retained unchanged in identity.
- **Twenty-two topic maps**, one per syllabus subtopic that carries enough structure to deserve
  its own, from demand and supply through to behavioural economics.
- **Ten synthesis maps**, which exist because the examined skill is connection rather than recall:
  elasticity and taxation, elasticity and intervention, externalities and sustainability, the
  interest rate as one instrument across three units, exchange rates and trade, growth and
  development, growth and inequality, growth and sustainability, efficiency against equity, and
  scarcity as the thread through the whole course.

Together they cover all thirty-one subtopics in the guide, which the coverage dashboard measures
rather than asserts.

Each map is a tree of nodes plus cross-links that cut across branches, which is what lets the
elasticity map reach tax incidence without redrawing elasticity inside the tax branch. Eighteen
node types carry a consistent visual language across every map, with a distinct shape and colour
each: concept, determinant, mechanism, model, diagram, calculation, application, evaluation,
stakeholder, judgement, TOK, exam, assumption, formula, misconception, evidence, real-world case
and policy.

The layout is computed, not positioned by hand. Branches are dealt to two sides of the central
concept and balanced by weight, so every map comes out landscape rather than as a tall column,
which is the shape a projector wants. A single renderer draws all forty-two, so adding a
forty-third means adding data and changing no code. Seven hundred and sixty-two nodes in total.

The thirteen modes:

| Mode | What it asks |
|---|---|
| Explore | Open any node. Detail, syllabus subtopic, diagram, calculation and dictionary entry appear beside the map. |
| Follow the mechanism | One causal pathway highlighted, the rest faded, read end to end. |
| Test yourself | Four nodes blanked; the distractors are real nodes from the same map, so the shape of the topic will not carry you. |
| Build the map | A pathway shuffled and reordered from memory. |
| Explain it | Say a branch in your own words against a sixty-second timer, then self-check against four criteria. |
| Repair it | A claim about the topic that is nearly right. Find the fault, correct it, and send it to the mistake book. |
| Connect | Build the chain that links this topic to another part of the course, in the order the argument requires. |
| What changes the result? | Move the condition the conclusion rests on and read what happens to the judgement. The point of the mode is that a conclusion which survives every condition was never an evaluation. |
| Exam | The questions the map's branches are actually assessed by, with the command term crosswalk. |
| Real world | One sourced application with its interpretation, model, limitation and publishing institution. |
| TOK lens | The knowledge question the topic raises, marked optional. |
| Classroom | One branch at a time, sized for a projector, with a timer and an exit question. |
| Revision | The map reduced to what has to be recoverable under examination conditions, ordered by what the progress record says is weakest. |
| List | The whole map as text. Not an afterthought: it is the default on phones and what screen readers and printouts use. |

Beneath every mode of every map sits the evaluation engine: the conditions under which that
topic's conclusion would change, each one to be written out with a direction, because a condition
named without a direction earns nothing.

**Mastery is earned, not opened.** Five strands per map (explored, mechanism followed, retrieval,
reconstructed, explained), and opening a map can move only the first. A self-test asserts that a
map with every node opened and nothing else done still scores below secure. Everything feeds the
existing skills model and revision queue rather than a parallel one: a branch marked difficult
goes to the mistake book, a branch set aside for later goes to the revision queue, and the daily
challenge draws from the maps on a rotation.

**Validation.** Every node reference is resolved against the thing it names. A node pointing at a
syllabus code, a diagram or a calculation that does not exist fails the build, and so does an
orphan node, a cycle, a cross-link leaving its own map, a pathway naming a node that is not
there, an objective using a vague verb, a real-world section asserting a figure of its own, or a
map laying out taller than it is wide. That suite found several defects during development,
including twelve nodes mapped to the wrong syllabus subtopic and three cross-links pointing out
of their own map.

**Every mindmap that can carry a case does.** Thirty-seven of the forty-two show one to three
real-world cases from the collection at their own subtopics, with an **Explore case** button into
the full record. The five that cannot say so rather than borrowing a case from somewhere else.

**The eighteenth node type is in use.** "Real-world case" asks where something has actually
happened, which is a different question from "Application", where the theory is used. Rather than
assert a new fact inside a map, each case node names a case the platform already holds in verified
form and hands the student to it, so the claim and its sourcing stay in one place.

**Stored progress was carried across, not discarded.** These were called brain maps in the
previous release. The storage key moved with the name, and the migration copies the old record
into the new one rather than starting anyone from zero. A test seeds a profile in the old shape,
runs the migration and asserts that every strand, every score and every unrelated key survives.

## Video learning

Thirty-four curated external videos across nineteen of the thirty-one subtopics, from nine
channels. The layer exists because watching is the cheapest form of study and the easiest to
mistake for progress, so nothing here is marked as learned because it was played.

Every entry states the subtopic it is filed against, whether the content is SL or HL, what it is
for (concept, diagram, calculation or revision), and why it was chosen rather than something
else. Beside each one sit three checkpoint questions, written against the syllabus content of
that subtopic rather than against the wording of the video, and the panel says so: a question
written from a transcript tests whether you were paying attention to a presenter, and a question
written from the guide tests whether you can now do the thing the subtopic asks for.

**Nothing loads until it is asked for.** The grid fetches still images only. The player element
does not exist anywhere in the document until the student presses Load the player, and it is then
created against YouTube's privacy-enhanced domain and never autoplays. A test asserts that both
the closed library and the opened viewer contain no player element at all.

**No broken image, ever.** Each still has two hosts and then a drawn placeholder generated inside
the page, which needs no network. A watchdog replaces any still that was requested and has not
arrived after five seconds, which matters because many schools block the video hosts outright.

**Verification is a build-time fact, stated with its date.** Every identifier was confirmed
against YouTube's public oEmbed endpoint, which returns a title and a channel for a video that
exists and is publicly available and an error for one that is private, deleted or restricted. The
titles and channels recorded are the ones that endpoint returned, not the ones a search result
displayed. Running times are not printed, because that endpoint does not return one and a figure
that has not been checked is not worth printing.

Videos are external resources selected for conceptual support. They are not official IB materials
unless explicitly identified as such, and none held here is so identified.

## Timed sessions

Revision fails in two directions. It fails when a student has ten minutes and opens nothing
because nothing fits ten minutes, and it fails when a student intends twenty minutes and spends
ninety re-reading. Naming the length first, and building the work to fit it, is what stops both.

Five lengths: five, fifteen, thirty, sixty and ninety minutes. Five minutes is three retrieval
items, enough to keep a topic warm and not enough to learn one; ninety minutes finishes with an
original examination task written under the clock. Each session is assembled when it starts, from the subtopics the progress record
shows as weak and the mistakes still open in the mistake book, so two sessions of the same length
are not the same session. The suggested minutes are scaled so that the steps add up to the length
chosen. Self-assessment is recorded at a lower weight than a marked attempt, and the panel says
so, because it is the student's reading of their own work.

## Exam DNA

A released examination paper is somebody else's copyright. The pattern inside it is not.

Exam DNA reads 212 released questions and their 990 parts, across twelve sessions of Papers 1, 2
and 3 at both levels, and records for each part only its syllabus subtopic, its command term, its
mark tariff and what the task demands: a diagram, a calculation, use of the data, evaluation, a
real-world example, a policy. It holds no question text, no stimulus, no markscheme and no
paraphrase of any of them. The corpus was machine-checked against the source papers with all
whitespace removed, and the longest run of consecutive words shared with any paper is zero.

What that buys a student is the shape of the paper rather than its contents:

- **The explorer** filters every recorded part by paper, level, session, subtopic, command term
  and demand, and reports how the marks actually fall.
- **Eleven archetypes** name the recurring task shapes, from the ten-mark mechanism to the
  Paper 3 recommendation, each with the demands it carries and the trap it sets.
- **The mark lens** shows what a two, four, ten or fifteen-mark tariff has historically asked
  for, so a student stops writing the same paragraph at every tariff.
- **The heatmap** puts subtopics against demands, which is where a revision plan should start.
- **The morpher** takes a recorded shape and builds an original task from it, written here. It is
  not a past question and the panel says so.
- **The museum** shows how the assessment has moved across the sessions analysed.
- **The source register** names all five papers analysed, what was taken from each and what was

## Accuracy corrections in this release

Six corrections applied at source in this release, each checked against the Economics guide held
in the project rather than against memory:

- **Five macroeconomic objectives, and external balance is not one of them.** The guide's
  macroeconomic objectives in 3.3 are low unemployment, a low and stable rate of inflation,
  sustainable economic growth, an equitable distribution of income, and, at HL, a sustainable
  level of government (national) debt. External balance appears in the guide as a goal of monetary
  policy and of fiscal policy, in 3.5 and 3.6, and it is presented that way here.
- **A sustainable level of government debt is filed under 3.3**, not 3.6, and every node that
  names it now carries that code.
- **Public goods: under-provision, not impossibility.** The analytical claim is that the free-rider
  problem leads to under-provision relative to the social optimum. The absolute form, that private
  provision must be zero, is listed as a misconception to avoid. The merit good distinction is kept.
- **Supply-side policy is not the only category that can raise output without raising the price
  level.** It is described as the category that raises potential output, with its lags and its
  opportunity cost stated as the evaluation.
- **The CPI is not "a basket nobody buys."** The basket is built from what households actually
  spend on. The real limitations, substitution, quality change, new goods and differences between
  households, are given instead, and the basket builder makes the last one visible.
- **Inflation, disinflation and deflation are kept apart.** Disinflation is a fall in the rate of
  inflation with the price level still rising; deflation is a fall in the price level itself.

Alongside those, three corrections that current examiner guidance requires:

- The **800-word limit is not one of the three criterion F rubric requirements.** It is a
  separate limit: moderators do not read beyond the 800th word. The IA command centre now marks
  the three rubric requirements as such and states plainly that the word limit is not one of them.
- **Supplementary articles and statistics are not appropriate** for a commentary. The commentary
  is assessed on the single submitted article, and the article checker now says so.
- **IA diagrams must be adapted to the article and explained in the commentary.** The diagram
  check asks what part of the article the diagram explains, which values and labels are adapted
  to it, and where that explanation appears, because a generic pasted plate cannot reach the
  top level of criterion A.

- **A defect in the question factory.** Every quiz entry in the topic dossiers passed its skill

- **The eighteenth node type was declared but unused.** "Real-world case" now appears in seven

- **Two stale counts in the interface.** A mindmap panel said "of the twelve node types" when

- **The independent-platform statement is now set out in full**, in the footer of every page and

  anywhere.

This holds for everything added in this release. The video player is created only on a click and
loaded from YouTube's privacy-enhanced domain; watching contacts YouTube, and nothing from this
platform is sent with it. An assignment link carries the chosen items and nothing else, so a
teacher can set work without a server and without anything about a student leaving their device.
The service worker caches this platform's own files and leaves every other origin alone.

## Run it locally

Download or clone the repository and open `index.html` in any modern browser. Double-clicking
the file is enough: there is no build step and no server required.

```bash
git clone https://github.com/<your-username>/arjun-agrawal-ib-economics.git
cd arjun-agrawal-ib-economics
# then open index.html
```

`index.html` is fully self-contained: the logo, portrait, diagrams and all logic are embedded.
You can email that one file to a student and it will work on its own.

The one thing that single file cannot carry with it is the Exam DNA corpus, which lives beside it
at `assets/data/exam-dna.js`. Open the file on its own and every Exam DNA surface says plainly
that the analysis file is not there; nothing else changes. Keep the folder together and Exam DNA
works, including offline once the platform has been installed.

For the installable version, the service worker needs a real origin rather than a `file://` path,
so serve the folder over HTTP:

```bash
python3 -m http.server 8000
# then open http://localhost:8000
```

## Publish it on GitHub Pages

**1. Create the repository**

Sign in to GitHub → **New repository** → name it `arjun-agrawal-ib-economics` → set it to
**Public** → **Create repository**. Do not add a README; this repository already has one.

**2. Upload the files**

On the empty repository page choose **uploading an existing file**, then drag in the contents
of this folder: `index.html`, `README.md`, `LICENSE`, `.gitignore`, `404.html`, `favicon.svg`
and the `assets` folder. Commit directly to the `main` branch.

> **Keep the folders.** Drag the `assets` folder itself, not the files inside it. If the files
> arrive flattened at the top level, the page still opens, but the ten carousel PDFs, the app
> icons, the offline cache and the external Exam DNA and real-world corpora all miss, because the
> page asks for them at `assets/carousels/`, `assets/icons/` and `assets/data/`. The expected
> layout is:
>
> ```text
> index.html  404.html  favicon.svg  manifest.webmanifest  service-worker.js  robots.txt
> assets/data/        exam-dna.js, real-world.js
> assets/icons/       app icons and apple-touch-icon.png
> assets/carousels/   economics-in-60-seconds-001.pdf … 010.pdf
> assets/brand/       source logo, monogram and portrait files (the page embeds its own copies)
> ```

> The `.github` folder is hidden on macOS. In Finder press `Cmd + Shift + .` to show hidden
> files before dragging, or skip it, see step 3b.

**3a. Enable Pages using the workflow (recommended)**

Repository → **Settings** → **Pages** → under **Build and deployment**, set **Source** to
**GitHub Actions**. The included workflow at `.github/workflows/pages.yml` publishes the site
on every push to `main`.

**3b. Or enable Pages without the workflow**

Repository → **Settings** → **Pages** → **Source: Deploy from a branch** → **Branch: `main`**,
**Folder: `/ (root)`** → **Save**. This works even if you did not upload the `.github` folder.

**4. Visit the live site**

After a minute or two it will be available at:

```
https://<your-username>.github.io/arjun-agrawal-ib-economics/
```

The Pages settings screen shows the exact URL once deployment finishes.

**A note on the repository name.** The site is published under a path, not at a domain root:
`https://<your-username>.github.io/<repository-name>/`. Every path inside the platform is
relative, so it works whatever you call the repository, and this was tested by serving the
package from a subdirectory: the service worker registers with the subpath as its scope, the
manifest and icons resolve, all ten carousel PDFs resolve, no request escapes the subpath, and
the site still works offline from there. You can rename the repository without editing anything.

**5. Update it later**

Edit or replace `index.html` in the repository (**Add file → Upload files**, keeping the same
filename) and commit. The site updates automatically within a minute.

**Optional: a custom domain:** Settings → Pages → **Custom domain**, then add the CNAME record
your domain provider asks for.
